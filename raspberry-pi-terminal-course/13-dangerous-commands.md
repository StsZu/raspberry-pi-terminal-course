# Урок 13 — Небезпечні команди

## Про що цей урок

Деякі команди Linux зручні, але одна помилка — втрата даних, нерабоча система або компрометація безпеки. На Raspberry Pi з SD-картою і одним SSH-вікном це особливо боляче.

**Головна мета — не вивчити всі команди Linux, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії на Raspberry Pi.**

---

## Золоті правила

1. Перед руйнівною дією: `pwd`, `ls -la`, прочитай команду вголос.
2. Не запускай `curl | bash` з невідомих сайтів.
3. `sudo` — тільки коли розумієш наслідки.
4. Бекап важливих даних перед `fdisk`, `mkfs`, масовим `chmod`.

---

## Каталог небезпечних команд

### `sudo`

| | |
|---|---|
| **Чому небезпечна** | Повні root-права — будь-яка помилка без захисту |
| **Коли легально** | apt, systemctl, файли в `/etc` |
| **Перевірка** | Чи дійсно потрібен root? Спробуй без sudo |
| **Альтернатива** | Мінімізуй sudo; окремий user для сервісів |
| **Ризик** | **Високий** (у поєднанні з іншими командами) |

---

### `rm -rf`

| | |
|---|---|
| **Чому небезпечна** | Безповоротне видалення без кошика; `rm -rf /` знищує систему |
| **Коли** | Видалення build-артефактів, старих проєктів (свідомо) |
| **Перевірка** | `pwd`, `ls`, використай `rm -r` без `-f` спочатку |
| **Альтернатива** | `trash-cli`, перейменуй папку в `_old` |
| **Ризик** | **ВИСОКИЙ** |

---

### `dd`

| | |
|---|---|
| **Чому небезпечна** | Побітове копіювання — неправильний `of=` затирає диск |
| **Коли** | Запис образу SD-карти (офіційний спосіб з raspberrypi.com) |
| **Перевірка** | Подвійно перевір `if=` і `of=` через `lsblk` |
| **Альтернатива** | Raspberry Pi Imager з GUI |
| **Ризик** | **ВИСОКИЙ** |

---

### `mkfs` / `fdisk` / `parted`

| | |
|---|---|
| **Чому небезпечні** | Форматування і розділи — втрата всіх даних на розділі |
| **Коли** | Підготовка нової SD/USB |
| **Перевірка** | `lsblk`, `df -h` — правильний пристрій? |
| **Альтернатива** | Imager; не чіпай `/dev/mmcblk0` на працюючій Pi без крайньої потреби |
| **Ризик** | **ВИСОКИЙ** |

---

### `chmod -R` / `chown -R`

| | |
|---|---|
| **Чому небезпечні** | Рекурсивна зміна прав на всю гілку — можна зламати систему або відкрити все світу |
| **Коли** | Виправлення прав конкретного проєкту |
| **Перевірка** | Вкажи конкретну папку, не `/` |
| **Альтернатива** | `chmod` на один файл; правильний `User=` у systemd |
| **Ризик** | **Високий** |

---

### `kill` / `killall`

| | |
|---|---|
| **Чому небезпечні** | Завершують процеси; `killall` — всі з іменем |
| **Коли** | Зависший скрипт |
| **Перевірка** | `ps aux | grep`, правильний PID |
| **Альтернатива** | `systemctl stop`, `kill -15` перед `kill -9` |
| **Ризик** | **Середній–високий** |

---

### `systemctl stop` / `systemctl disable`

| | |
|---|---|
| **Чому небезпечні** | Зупиняють критичні сервіси (мережа, ssh) |
| **Коли** | Керування своїм service |
| **Перевірка** | Який саме unit? `systemctl status` |
| **Альтернатива** | `restart` замість `stop` для тесту |
| **Ризик** | **Середній** |

---

### `curl | bash` / `wget | bash`

| | |
|---|---|
| **Чому небезпечні** | Завантажує скрипт з інтернету і **одразу виконує** без перегляду |
| **Коли** | Офіційні install-скрипти від довірених вендорів (обережно) |
| **Перевірка** | Завантаж окремо, прочитай: `curl -fsSL URL -o install.sh`, потім `less install.sh` |
| **Альтернатива** | `apt install`, офіційна документація, manual steps |

**Особливо небезпечно:**

```bash
curl -fsSL https://example.com/install.sh | bash
```

Це зручно для швидкого setup, але якщо сервер скомпрометований або URL підмінений — ти даєш root (через sudo у скрипті) невідомому коду.

**Безпечніший підхід:**

```bash
curl -fsSL https://example.com/install.sh -o install.sh
less install.sh
# якщо все ок:
bash install.sh
```

| **Ризик** | **ВИСОКИЙ** |

---

### `sudo reboot` / `sudo shutdown -h now`

| | |
|---|---|
| **Чому «небезпечні»** | Не руйнують дані навмисно, але **негайно завершують роботу Pi** |
| **Коли** | Після оновлень, зміни конфігів, кінець роботи |
| **Перевірка** | Збережені файли? Ні активних `apt upgrade`? Інші користувачі SSH? |
| **Альтернатива** | `sudo shutdown -h +5 "Reboot in 5 min"` — час попередити |

```bash
sudo reboot              # перезавантаження
sudo shutdown -h now     # вимкнення зараз
sudo shutdown -r +5      # reboot через 5 хвилин
```

| **Ризик** | **Середній** (операційний — втрата несинхронізованої роботи) |

---

## Шпаргалка «стоп-сигнал»

Якщо бачиш у команді комбінацію — **зупинись**:

- `rm -rf` + шлях, який не перевірив
- `dd` + `of=/dev/...`
- `curl` + `| bash`
- `chmod 777 -R /`
- `>` або `>>` у `/etc/` без бекапу

---

## Практичне завдання

1. На Pi створи папку `~/danger-test`. Додай файл. Видали через `rm file` (не `-rf`).
2. Спробуй `curl -fsSL https://example.com` **без** pipe в bash — тільки подивись вивід.
3. Запиши власними словами, чому `curl | bash` небезпечний.
4. `sudo shutdown -h +10` — потім `sudo shutdown -c` (скасувати), щоб не вимкнути Pi.
5. Склади список з 5 команд, які ніколи не запустиш без `pwd`/`ls`.

- [ ] Перед `dd`/`mkfs` перевіряю `lsblk`
- [ ] `sudo` — свідомо, не за замовчуванням

# Урок 1 — SSH і перший вхід

## Про що цей урок

SSH (Secure Shell) — спосіб віддалено керувати Raspberry Pi з Mac через Terminal. Ти вводиш команди на Mac, а виконуються вони на Pi. Це основа всієї подальшої роботи: автоматизація, Python, GPIO, сервіси — все через SSH.

**Ключові поняття:**

- **username** — ім'я користувача на Pi (наприклад `stanislav`, не обов'язково `pi`)
- **hostname** — ім'я Pi в мережі (часто `raspberrypi.local`)
- **IP-адреса** — числова адреса Pi в локальній мережі (наприклад `10.0.0.50`)

**Головна мета — не вивчити всі команди Linux, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії на Raspberry Pi.**

---

## Перевірка перед SSH

Перед підключенням переконайся:

1. Чи Raspberry Pi увімкнена.
2. Чи Pi підключена до Wi-Fi або Ethernet.
3. Чи Mac і Pi в одній мережі.
4. Чи пінгується `raspberrypi.local` або IP-адреса.
5. Чи правильний username.
6. Чи увімкнений SSH на Raspberry Pi (Raspberry Pi OS: Settings → Interfaces → SSH → Enable).

## Команди

### `ping raspberrypi.local` / `ping <ip-address>`

| | |
|---|---|
| **Що робить** | Надсилає тестові пакети на пристрій, перевіряє чи він у мережі |
| **Коли** | Перед SSH, коли Pi «не знаходиться» |
| **Приклад** | `ping raspberrypi.local` або `ping 10.0.0.50` |
| **Типовий результат** | `64 bytes from 10.0.0.50: icmp_seq=1 ttl=64 time=2.3 ms` |
| **Типові помилки** | `Request timeout` — Pi вимкнена, інша мережа, або неправильна адреса |
| **Ризик** | **Низький** |

Натисни `Ctrl+C`, щоб зупинити ping.

---

### `ssh <user>@<hostname>` / `ssh <user>@<ip>`

| | |
|---|---|
| **Що робить** | Відкриває зашифровану сесію Terminal на віддаленому комп'ютері |
| **Коли** | Щоразу, коли треба працювати на Pi з Mac |
| **Приклад** | `ssh stanislav@raspberrypi.local` або `ssh stanislav@10.0.0.50` |
| **Типовий результат** | Запит пароля → prompt типу `stanislav@raspberrypi:~ $` |
| **Типові помилки** | `Connection refused` — SSH вимкнений; `Permission denied` — неправильний пароль або user; `Could not resolve hostname` — Pi не в мережі |
| **Ризик** | **Низький** (при правильному user і мережі) |

При першому підключенні з'явиться питання про fingerprint — введи `yes`.

---

| | |
|---|---|

| **Приклад** | `hostname` |
| **Типовий результат** | `raspberrypi` |

| | |

| **Коли** | Перевірити під яким user ти залогінений |
| **Приклад** | `whoami` |

|---|---|

### `exit`

| | |
|---|---|
| **Що робить** | Закриває SSH-сесію, повертає на Mac |
| **Коли** | Закінчив роботу на Pi |
| **Приклад** | `exit` |
| **Типовий результат** | `Connection to raspberrypi.local closed.` |
| **Типові помилки** | — |
| **Ризик** | **Низький** |

## Типовий сценарій першого входу

На **Mac** (локальний Terminal):

```bash
ping raspberrypi.local
ssh stanislav@raspberrypi.local
```

Після входу на **Pi**:

```bash
whoami
hostname
pwd
exit
```

---

## Практичне завдання

1. З Mac: `ping raspberrypi.local` (або IP Pi). Переконайся, що є відповіді.
2. `ssh stanislav@raspberrypi.local` — увійди (заміни `stanislav` на свій username).
3. На Pi виконай: `whoami`, `hostname`, `pwd`. Запиши результати.
4. `exit` — повернись на Mac.

**Бонус:** знайди IP Pi в налаштуваннях роутера або на екрані Pi (якщо є монітор) і підключись через IP замість `.local`.

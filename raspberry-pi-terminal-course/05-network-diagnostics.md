# Урок 5 — Діагностика мережі

## Про що цей урок

Raspberry Pi для SSH, Git, API і оновлень потребує робочої мережі. Цей урок — знайти IP, перевірити шлюз, інтернет, DNS, порти і Wi-Fi.

**Головна мета — не вивчити всі команди Linux, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії на Raspberry Pi.**

---

## Команди

### `hostname -I`

| | |
|---|---|
| **Що робить** | Показує IP-адреси Pi (швидкий спосіб) |
| **Коли** | Потрібен IP для SSH з Mac |
| **Приклад** | `hostname -I` |
| **Результат** | `10.0.0.50` або кілька адрес |
| **Ризик** | **Низький** |

---

### `ip addr`

| | |
|---|---|
| **Що робить** | Детальна інформація про мережеві інтерфейси |
| **Коли** | Wi-Fi (`wlan0`) vs Ethernet (`eth0`), MAC, стан UP/DOWN |
| **Приклад** | `ip addr` |
| **Ризик** | **Низький** |

---

### `ip route`

| | |
|---|---|
| **Що робить** | Таблиця маршрутизації, включно з default gateway |
| **Коли** | Pi не виходить в інтернет — перевірити шлюз |
| **Приклад** | `ip route` |
| **Результат** | `default via 10.0.0.1 dev wlan0` |
| **Ризик** | **Низький** |

---

### `ping`

| | |
|---|---|
| **Що робить** | Перевірка доступності хоста (ICMP) |
| **Коли** | Діагностика локальної мережі і інтернету |
| **Приклад** | `ping 8.8.8.8` (IP), `ping google.com` (DNS + мережа) |
| **Помилки** | IP працює, домен ні — проблема DNS |
| **Ризик** | **Низький** |

---

### `traceroute <host>`

| | |
|---|---|
| **Що робить** | Шлях пакетів до хоста |
| **Коли** | Де обривається з'єднання |
| **Приклад** | `traceroute google.com` |
| **Ризик** | **Низький** |

---

### `dig` / `nslookup`

| | |
|---|---|
| **Що робить** | Запит DNS — перетворення імені в IP |
| **Коли** | `ping google.com` не працює, а `ping 8.8.8.8` працює |
| **Приклад** | `dig google.com`, `nslookup google.com` |
| **Ризик** | **Низький** |

---

### `curl` / `wget`

| | |
|---|---|
| **Що робить** | HTTP-запит / завантаження файлу |
| **Коли** | Перевірити доступ до веб-сервісу або API |
| **Приклад** | `curl https://example.com`, `curl -I https://google.com` |
| **Ризик** | **Низький** (обережно з невідомими URL) |

---

### `ss -tulpn`

| | |
|---|---|
| **Що робить** | Відкриті порти і процеси, що їх слухають |
| **Коли** | Чи працює твій сервіс на порту 8080, 22 тощо |
| **Приклад** | `ss -tulpn` |
| **Результат** | `LISTEN 0 128 0.0.0.0:22` — SSH |
| **Ризик** | **Низький** |

---

### `nmcli`

| | |
|---|---|
| **Що робить** | Керування NetworkManager (Wi-Fi, Ethernet) |
| **Коли** | Статус Wi-Fi, підключення |
| **Приклад** | `nmcli device status`, `nmcli connection show` |
| **Ризик** | **Низький** (читання); **середній** (зміна налаштувань) |

---

### `rfkill list`

| | |
|---|---|
| **Що робить** | Чи заблокований Wi-Fi/Bluetooth програмно або апаратно |
| **Коли** | Wi-Fi «зник» після оновлення або помилки |
| **Приклад** | `rfkill list` |
| **Результат** | `Soft blocked: yes` — треба розблокувати |
| **Ризик** | **Низький** |

---

## Сценарій діагностики «немає інтернету»

```bash
hostname -I
ip addr
ip route
ping 8.8.8.8          # інтернет на рівні IP?
ping google.com       # DNS працює?
curl https://example.com
rfkill list           # Wi-Fi не заблокований?
ss -tulpn             # SSH слухає порт 22?
```

---

## Практичне завдання

1. Запиши IP Pi: `hostname -I`.
2. Знайди default gateway: `ip route | grep default`.
3. `ping 8.8.8.8` і `ping google.com` — порівняй результати.
4. `curl -I https://example.com` — який HTTP-код?
5. `ss -tulpn | grep 22` — чи слухає SSH?
6. `rfkill list` — чи Wi-Fi не заблокований?

# Урок 6 — Стан системи і процеси

## Про що цей урок

Raspberry Pi 5 — компактний комп'ютер з обмеженнями RAM, нагрівом і живленням. Треба вміти перевірити температуру, пам'ять, диск, завантажені процеси — і знати, коли Pi «задыхається».

**Головна мета — не вивчити всі команди Linux, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії на Raspberry Pi.**

### `vcgencmd measure_temp` ⭐

| | |
|---|---|
| **Що робить** | Температура CPU Raspberry Pi (у градусах Цельсія) |
| **Коли** | Перегрів, throttling, погане охолодження |
| **Приклад** | `vcgencmd measure_temp` |
| **Результат** | `temp=52.3'C` |
| **Помилки** | Команда тільки на Raspberry Pi (не на Mac) |
| **Ризик** | **Низький** |

Нормально: 40–60°C під навантаженням. Вище 80°C — перевір радіатор/вентилятор і живлення.

---

### `vcgencmd get_throttled` ⭐

| | |
|---|---|
| **Що робить** | Показує історію throttling — зниження частоти через перегрів або **недостатнє живлення** |
| **Коли** | Pi «гальмує», перезавантажується, нестабільна робота під навантаженням |
| **Приклад** | `vcgencmd get_throttled` |
| **Результат** | `throttled=0x0` — все добре |
| **Ризик** | **Низький** |

**Чому це важливо для Raspberry Pi:**

Значення відмінне від `0x0` означає, що Pi вже стикався з:
- **недостатнім живленням** (слабкий БЖ, тонкий USB-кабель) — найчастіша причина на Pi 5;
- **перегрівом** — throttling знижує частоту CPU;
- **undervoltage** — нестабільна робота GPIO, USB, SD-карти.

Перевіряй `get_throttled` після налаштування сервісів, GPIO і при «дивних» збоях. Це діагностика, якої немає на звичайному Linux-сервері.

Розшифровка (спрощено): біти в hex показують, *чи були* події з моменту увімкнення. `0x0` = проблем не зафіксовано.

| | |
|---|---|

## Типовий health-check Pi

```bash
vcgencmd measure_temp
vcgencmd get_throttled
free -h
df -h
du -sh ~/projects
uptime
ps aux | grep python
```

## Практичне завдання

1. `vcgencmd measure_temp` і `vcgencmd get_throttled` — запиши значення.
2. `free -h` і `df -h` — скільки вільної RAM і місця на `/`?
3. `du -sh ~` — розмір домашньої папки.
4. Запусти `top` на 30 секунд — який процес найбільше навантажує CPU?
5. `ps aux | grep ssh` — знайди SSH-процес.

**Контрольне питання:** що означає `throttled=0x0` і чому `get_throttled` важливіша за звичайний `top` для Pi?
